# BathCraft — Bathroom Planner PWA

BathCraft turns a homeowner's inch-tape measurements and preferences into a single
shared **Project Brief**: a scaled, clearance-correct **2D plan** plus an itemised
**material + cost + time estimate** that the homeowner and their contractor agree on
*before* spending. India market, English / हिन्दी, installable PWA.

This repo is the **planner app** — the product the marketing landing page
(<https://bathcraft-pi.vercel.app>) hands users into via "Start Planning Free".

## Stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind v4** (CSS-token config in `src/app/globals.css`)
- **Zustand** for wizard/project state
- **PWA**: `src/app/manifest.ts` + theme/viewport in `src/app/layout.tsx`
- Deploys on **Vercel**

## Getting started

```bash
npm install
cp .env.example .env.local   # optional — app runs fully offline without it
npm run dev                  # http://localhost:3000  → redirects to /planner
```

Other scripts: `npm run build`, `npm run start`, `npm run lint`, `npx tsc --noEmit`.

## Project structure

```
src/
  app/                 routes: /planner (wizard), /bathrooms /guides /docs, manifest, layout
  components/
    shell/             AppHeader, BottomNav, ProgressBar, WizardShell, ComingSoon
    ui/                design-system primitives (MaterialIcon, …)
    providers.tsx      theme + i18n providers
  lib/
    types.ts           the domain model (Room, StyleChoice, Fixtures, Plan, Estimate, Project)
    defaults.ts        default project values + dimension bounds
    units.ts           inch/cm/ft + INR + area helpers
    theme/             light/dark provider (tokens live in globals.css)
    i18n/              en/hi dictionaries + provider
    auth/              provider-agnostic auth seam (local now, Supabase SSO in M6)
    db/                provider-agnostic data seam (localStorage now, Supabase in M6)
    store/             Zustand project store (write-through to the data seam)
    layout/            (M3) rule-based 2D layout engine  — pure, test-first
    estimate/          (M4) BOM + cost + time engine      — pure, test-first
```

### Integration seams (important)

`lib/auth` and `lib/db` are interfaces with local implementations today. When the
teammate's Supabase (auth + database) is ready, a Supabase implementation of each is
added and selected via env in `getAuthProvider()` / `getProjectStore()` — **no consumer
code changes**. Keep all Supabase access behind these seams. See `.env.example`.

The design system is extracted 1:1 from the original Stitch wireframe: the full
light/dark palette lives as CSS custom properties in `globals.css`; components read
them via `var(--color-*)`. Keep new UI on these tokens so light/dark stays consistent.

## Contributing (team workflow)

- **Never commit to `main` directly.** Branch: `feat/<short-name>`, `fix/<short-name>`.
- Open a PR into `main`; keep PRs focused on one milestone/step.
- Before pushing: `npx tsc --noEmit` and `npm run lint` must pass.
- The two engines (`lib/layout`, `lib/estimate`) are **test-first** — add/adjust unit
  tests with any change to them.
- Don't edit auto-generated files (`AGENTS.md` is regenerated by `next dev`;
  `next-env.d.ts`).
- This repo is intentionally self-contained and env-driven so it can be **merged into
  the landing repo before launch** — avoid hard-coding absolute paths or coupling to a
  standalone root.
